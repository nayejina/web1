# CloudConverter 코드 가이드

이 문서는 코드를 처음 보는 사람이 **"이 프로그램이 어떻게 짜여 있고, 버튼 하나를 누르면 안에서 무슨 일이 일어나는지"** 를 이해하고, 직접 고쳐 볼 수 있도록 정리한 것입니다.
문서의 파일 경로는 모두 `cloud-converter-demo/` 기준입니다.

---

```
 ┌──────────────── CloudConverter.App (화면) ────────────────┐
 │  MainForm  LogViewerForm  CloudBrowserForm  AboutForm      │

 └───────────────────────────┬───────────────────────────────┘
                             │ "이 파일 변환해 줘" / "결과 코드 1000"
 ┌───────────────────────────▼───────────────────────────────┐
 │  CloudConverter.Core (규칙)                                 │
```

- **Core** 는 "규칙"만 담고 화면을 모릅니다. 그래서 자동 테스트로 검사하기 쉽고, 리눅스에서도 테스트가 돌아갑니다.
- **App** 은 사용자가 보는 화면과 Windows 전용 기능을 담당하고, 판단이 필요하면 Core 에 물어봅니다.
- 이렇게 나누면 "화면은 그대로 두고 변환 방식만 MIP SDK 로 바꾸기" 같은 일이 쉬워집니다 (실제로 MIP 버전이 이렇게 만들어졌습니다).

## 2. 프로그램이 켜질 때 (실행 흐름)

시작점은 `src/CloudConverter.App/Program.cs` 의 `Main` 함수입니다. C# 프로그램은 항상 `Main` 에서 시작합니다.

```
CloudConverter.exe 실행
  │
  ├─ ① 실행 인자 확인
  │     --register / --unregister  → 우클릭 메뉴 등록/해제만 하고 끝
  │     --mip "파일" / --drm "파일"  → 우클릭 메뉴로 실행됨 (LaunchRequest 로 정리)
  │
  ├─ ② 이미 켜진 CloudConverter 가 있나? (SingleInstance)
  │     있으면 → 그 창에 "이 파일 추가해 줘" 를 전달하고 이 프로세스는 바로 종료
  │     없으면 → 내가 첫 번째. 다른 프로세스의 요청을 받을 준비 (파이프 서버 시작)
  │
  ├─ ③ AppServices 생성: 설정 JSON 읽기, 변환 엔진·로그 저장소 준비, 샘플 파일 생성
  │
  ├─ ④ 우클릭 메뉴가 등록 안 되어 있으면 레지스트리에 등록
  │
  └─ ⑤ MainForm(메인 창) 생성 → Application.Run(form) : 창이 닫힐 때까지 여기서 대기
```

### ② "창이 하나만 뜨는" 원리 — `Services/SingleInstance.cs`

탐색기에서 파일 10개를 선택하고 우클릭 → "MIP로 변환" 을 누르면, Windows 는 **exe 를 10번 실행**합니다 (파일마다 한 번씩).
그대로 두면 창이 10개 뜨므로 다음 두 가지 Windows 기능을 씁니다.

- **Mutex(뮤텍스)**: 이름 붙은 깃발. 가장 먼저 실행된 프로세스만 깃발을 잡을 수 있어 "내가 첫 번째인지" 알 수 있습니다.
- **Named Pipe(이름 있는 파이프)**: 프로세스끼리 데이터를 주고받는 통로. 2~10번째 프로세스는 첫 번째 프로세스에 `"Mip\n파일경로"` 를 보내고 종료합니다.
- 첫 번째 프로세스는 받은 요청을 `MainForm.EnqueueExternalRequest` 로 넘겨 목록에 파일을 추가합니다.

### ④ 우클릭 메뉴 원리 — `Services/ContextMenuRegistrar.cs`

탐색기 우클릭 메뉴는 **레지스트리**(Windows 설정 저장소)에 적힌 내용을 읽어 만들어집니다. 프로그램은 다음 위치에 값을 씁니다.

```
HKEY_CURRENT_USER\Software\Classes\SystemFileAssociations\.docx\shell\CloudConverterDemo
    MUIVerb     = "CloudConverter(demo)"        ← 메뉴에 보이는 이름
    SubCommands = ""                            ← 하위 메뉴가 있다는 표시
    shell\01mip\command = "C:\...\CloudConverter.exe" --mip "%1"   ← "MIP로 변환" 을 누르면 실행할 명령
    shell\02drm\command = "C:\...\CloudConverter.exe" --drm "%1"
```

`%1` 자리에 Windows 가 우클릭한 파일 경로를 넣어 exe 를 실행합니다. 이것이 ① 의 `--mip "파일"` 입니다.
`HKEY_CURRENT_USER`(현재 사용자) 아래에 쓰므로 관리자 권한이 필요 없습니다.
레지스트리를 직접 보고 싶다면 `Win+R` → `regedit` → 위 경로로 이동해 보세요.

## 4. 핵심 동작 원리

### 4-1. 화면 배치 — `MainForm.LayoutControls()`

모든 컨트롤 위치를 **숫자로 직접 계산**해서 놓습니다. 기준 숫자는 실제 Converter 툴 화면에서 잰 값이며 `MainForm.cs` 위쪽 상수에 모여 있습니다.

```csharp
private const int MarginLeft = 17, MarginRight = 14;   // 좌우 여백
private const int ColumnGap = 35;                      // 왼쪽 열과 오른쪽 열 사이
private const int RightColumnWidth = 384;              // 오른쪽 열 최소 폭
private const int ComboWidth = 150, FindWidth = 60;    // 콤보박스, 찾기 버튼 폭
```

- 창 크기가 바뀔 때마다(`OnLayout`) `LayoutControls()` 가 다시 계산합니다.
- 오른쪽 열은 최소 384 를 지키고, 남는 폭을 왼쪽 열이 가져갑니다.
- `Px(숫자)` 는 **화면 배율 보정**입니다. 125% 배율 PC 에서는 `Px(384)` = 480 이 됩니다.
- 창 최소 크기는 `ApplyMinimumSize()` 에서 "오른쪽 열 최소 폭 × 2" 로 정합니다.

### 4-2. 버튼이 켜지고 꺼지는 규칙 — `MainForm.UpdateUiState()`

기획서 13p 의 활성화 정책이 **이 함수 하나**에 모여 있습니다. 무언가 바뀔 때마다(형식 선택, 파일 추가, 저장 위치 선택 …) 이 함수를 불러 모든 버튼 상태를 다시 정합니다.

```csharp
_targetCombo.Enabled = hasFormat && idle && _targetList.Items.Count == 0;   // 형식 선택됨 + 변환 중 아님 + 목록 비어 있음
_startButton.Enabled = _running
    || (hasFormat && (가능한 파일 > 0 || 폴더 > 0) && (동일 폴더 저장 || 저장 위치 선택됨));
```

"이 버튼이 왜 안 눌리지?" 가 궁금하면 이 함수를 보면 됩니다.

### 4-3. 위치 콤보박스 — `RefreshTargetCombo()` / `RefreshSaveCombo()`

정책 파일(`conversion-policy.json`)의 "MIP: 내 드라이브 → [내 드라이브, OneDrive, SharePoint]" 같은 규칙을 읽어 콤보박스 항목을 채웁니다.
대상 위치를 바꾸면 저장 위치 목록이 그에 맞게 줄어들고, 반대도 마찬가지입니다. 실제 판단은 Core 의 `ConversionPolicy.TargetsFor()` 가 합니다.

### 4-4. 파일이 목록에 들어갈 때 — `MainForm.AddTargets()`

드래그 앤 드롭, 찾기, 우클릭 메뉴 모두 결국 이 함수로 모입니다.

1. 같은 파일이 이미 있으면 건너뜀
2. 파일 크기 읽기, 폴더면 `<폴더>`
3. `Engine.CheckEligibility()` 로 **가능/불가** 판정 (확장자 → `ExtensionRules`, 제외 폴더 → `ConversionPolicy`)
4. 목록에 한 줄 추가 (`TargetItem` 을 `Tag` 에 붙여 둠)
5. `UpdateUiState()` 로 버튼 상태 갱신

### 4-5. 변환 시작부터 끝까지 — `MainForm.Conversion.cs`

```
[변환 시작] 클릭
  └─ StartConversion()
       ├─ 확인 팝업 "변환 대상 파일: N개 …"          (불가 파일은 개수에서 제외)
       ├─ (MIP 버전만) 로그인·레이블 선택            IPreparableEngine.PrepareAsync
       ├─ 폴더 안 파일 목록 수집                     EnumerateFolder (백그라운드)
       ├─ 개수/용량 제한 검사                        ConversionPolicy.MaxFileCount …
       ├─ 변환 상태 목록에 전부 "준비 중" 으로 올림
       └─ 파일마다 반복 ─ ProcessFile()
             ├─ 저장 경로 결정          DestinationPlanner.Plan()   → "...\견적서(1).xlsx"
             ├─ 실제 변환 (백그라운드)   Engine.Convert()            → 결과 코드 1000 / 2003 / 3001 …
             ├─ 진행 막대 애니메이션     AnimateUntil / AnimateTo
             ├─ 결과 코드 → 분류        LogClassification           → 성공/실패/스킵 + 문구
             └─ 로그 한 줄 저장          LogStore.Append()
  └─ 끝나면: 성공 항목 목록에서 제거, 요약 팝업 "성공 n개 / 실패 n개 / 스킵 n개"
```

#### 결과 코드라는 아이디어

엔진은 "성공/실패" 라는 **글자를 돌려주지 않고 숫자 코드만** 돌려줍니다 (`ResultCodes` 클래스).

| 코드 | 뜻 |
|---|---|
| 1000, 1001 | 성공 (MIP / DRM) |
| 2001 ~ 2009 | 실패 (이미 암호화됨, 접근 실패, 권한 없음 …) |
| 3001 ~ 3006 | 스킵 (지원 안 하는 확장자, 크기 0 …) |
| 9001, 9002 | 폴더 시작/완료 알림 |

코드를 "성공/실패/스킵" 과 화면 문구로 바꾸는 일은 `config/log-classification.json` 이 합니다.
그래서 **JSON 만 고치면 분류 기준과 문구를 바꿀 수 있고**, 로그 파일에는 코드만 저장되어 있으므로 예전 로그도 새 분류로 다시 보입니다.

#### 화면이 멈추지 않는 이유 — `async` / `await` / `Task.Run`

WinForms 에서는 화면을 그리는 스레드(UI 스레드)가 하나뿐입니다. 여기서 오래 걸리는 일(파일 복사, MIP 암호화)을 하면 창이 "응답 없음" 이 됩니다.

```csharp
var work = Task.Run(() => _services.Engine.Convert(path, dest, format)); // 무거운 일은 다른 스레드로
await AnimateUntil(row, work, duration);  // 기다리는 동안 UI 스레드는 진행 막대를 계속 그림
var outcome = await work;                 // 끝나면 결과 받기
```

`await` 는 "끝날 때까지 기다리되, 그 사이에 화면은 계속 움직이게 해 줘" 라는 뜻입니다.

#### 시연판이 "변환" 하는 방법 — `ConversionEngine.Convert()`

실제 암호화 대신 다음 순서로 **판정 → 복사** 합니다.

1. 원본이 없음 → 2006 / 확장자 불가 → 3001 / 제외 폴더 → 3004 / 크기 0 → 3002
2. 파일명에 `_skip` → 3003, 이번 실행에서 이미 변환한 파일 → 2001
3. 파일 내용이 실제로 암호화된 Office/PDF → 2003 (`LooksEncrypted`: docx 는 원래 zip 인데, 암호화되면 OLE 형식으로 바뀌는 점을 이용)
4. 파일명에 `_fail` → 2005
5. 통과하면 **원본을 저장 경로로 복사**하고, "변환한 파일" 로 기억 → 1000

### 4-6. 진행 막대를 직접 그리기 — `DrawStatusSubItem()`

WinForms 목록(ListView) 에는 진행 막대가 없어서 `OwnerDraw = true` 로 두고 **칸마다 직접 그립니다**.
`StatusRow.Style` 값(Pending/Running/Success/Fail/Skip/Info) 에 따라 흰 칸·파란 막대·회색·연파랑을 칠하고 글자를 씁니다.
색은 모두 `UI/Theme.cs` 에 있으므로 **색을 바꾸고 싶으면 Theme.cs 만 고치면 됩니다.**

### 4-7. 설정 파일 — `JsonConfig.Load()`

exe 옆 `config\*.json` 을 읽어 C# 객체로 바꿉니다. JSON 의 이름과 C# 속성 이름이 같으면 자동으로 채워집니다.

```json
// conversion-policy.json 일부
"Demo": { "ForceFailKeywords": ["_fail", "[실패]"], ... }
```
```csharp
// ConversionPolicy.cs
public sealed class DemoRules { public List<string> ForceFailKeywords { get; set; } = ...; }
```

파일이 없거나 문법이 틀리면 코드에 적힌 기본값을 쓰고, 시작할 때 "일부 설정을 읽지 못해…" 팝업으로 알려 줍니다.

### 4-8. 시연판과 MIP 버전 — 같은 소스, 두 개의 exe

`src/CloudConverter.App/CloudConverter.App.csproj` (프로젝트 설정 파일) 에서 `Edition` 값에 따라 달라집니다.

| | 시연판 (기본) | MIP (`-p:Edition=Mip`) |
|---|---|---|
| exe 이름 | CloudConverter | CloudConverterMip |
| 포함 코드 | `Mip\` 폴더 제외 | `Mip\` 폴더 포함, `MIP_EDITION` 기호 정의 |
| 추가 패키지 | 없음 | MIP SDK, MSAL(로그인) |
| 설정 | `config\` | `config-mip\` |

코드 안에서는 `#if MIP_EDITION … #else … #endif` 로 갈라집니다 (`AppServices.cs`, `AppEdition.cs`).

## 5. MIP 버전 엔진 — `Mip/MipConversionEngine.cs`

`IConversionEngine` 약속을 똑같이 지키기 때문에 **화면 코드는 한 줄도 바꾸지 않고** 엔진만 갈아 끼웠습니다.

```
PrepareAsync (변환 시작 직전, 1회)
  ├─ MSAL 로 Microsoft 365 로그인 (브라우저)         MipAuthDelegate.SignInAsync
  ├─ MIP SDK 초기화 → 프로필 → 엔진                 CreateEngineAsync
  └─ 레이블 선택 창                                 LabelPickerForm

Convert (파일마다)
  ├─ engine.CreateFileHandlerAsync(파일)            파일 열기
  ├─ 이미 보호됨? → 2003 / 같은 레이블? → 2001
  ├─ handler.SetLabel(레이블)  또는  handler.RemoveProtection()
  ├─ handler.CommitAsync(임시파일) → 최종 경로로 이동
  └─ SDK 예외 → 결과 코드 (MapException)            권한 없음 → 2005, 네트워크 → 2008 …
```

MIP SDK 가 토큰이 필요할 때 `MipAuthDelegate.AcquireToken()` 을 부르고, 여기서 MSAL 로 토큰을 받아 돌려줍니다.

## 6. 자동 테스트 — `tests/CloudConverter.Core.Tests/CoreTests.cs`

Core 의 규칙이 맞는지 **코드로 검사**합니다 (현재 34개). 예:

```csharp
[InlineData("a.txt", "a.ptxt")]   // .txt 를 MIP 변환하면 .ptxt 가 되어야 한다
public void MipProtectedName(string input, string expected) =>
    Assert.Equal(expected, _rules.GetMipProtectedFileName(input));
```

규칙을 고친 뒤 테스트를 돌리면 다른 곳이 깨졌는지 바로 알 수 있습니다. 테스트가 지키는 것: 확장자 규칙, 위치 정책, 파일명 중복 규칙, 엔진 판정(성공/실패/스킵), 로그 저장/읽기, 샘플 파일.

## 10. Claude 에게 물어볼 때 요령

- **파일과 함수 이름을 같이** 말하기: "`MainForm.cs` 의 `UpdateUiState` 에서 저장 버튼이 언제 꺼지는지 설명해 줘"
- **증상 + 재현 순서** 를 말하기: "MIP 선택 → 폴더 드래그 → 변환 시작을 누르면 ○○ 팝업이 뜬다"
- **한 번에 하나씩** 요청하고, 고친 뒤 직접 실행해서 확인하기
- 모르는 단어가 나오면 "이 코드에서 `await` 가 하는 일을 예를 들어 설명해 줘" 처럼 코드에 붙여서 묻기
