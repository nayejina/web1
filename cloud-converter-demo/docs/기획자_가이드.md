# CloudConverter 시연판 — 기획자 가이드

코드를 읽지 않고도 **각 기능이 어떤 방식으로 만들어졌고, 왜 그렇게 했으며, 바꾸고 싶을 때 무엇을 건드리면 되는지** 알 수 있도록 정리한 문서입니다.

- **[설정]** 표시: 프로그램 폴더의 `config` 안 파일(메모장으로 열 수 있는 텍스트)만 고치면 바뀝니다. 개발 없이 직접 가능합니다.
- **[개발]** 표시: 코드 수정이 필요합니다. 개발자(또는 Claude)에게 요청할 때 함께 적힌 **"담당 위치"** 를 같이 전달하면 빠릅니다.

---

## 0. 전체 그림

```
 ┌───────────── 화면 (사용자가 보는 것) ─────────────┐
 │ 메인 창 · 로그 보기 · 클라우드 탐색 · 프로그램 정보 │
 └──────────────┬───────────────────────────────────┘
                │ "이 파일 변환해 줘"   ↑ "결과: 코드 1000"
 ┌──────────────▼───────────────────────────────────┐
 │ 규칙 (판단하는 부분)                                │
 │ 위치 조합 · 확장자 · 파일명 중복 · 성공/실패 판정    │
 └──────────────┬───────────────────────────────────┘
                │ 규칙 값은 여기서 읽음
 ┌──────────────▼───────────────────────────────────┐
 │ 설정 파일 (config 폴더)  ← 기획자가 직접 바꿀 수 있는 곳 │
 └──────────────────────────────────────────────────┘
```

설계 원칙은 세 가지입니다.

1. **화면과 규칙을 분리** — 화면은 "보여 주기", 판단은 "규칙" 이 담당합니다. 그래서 화면은 그대로 두고 변환 방식만 MIP 로 갈아 끼운 MIP 버전을 만들 수 있었습니다.
2. **고객사마다 달라질 값은 설정 파일로** — 기획서에 "고객사에 따라 변동 가능" 이라고 적힌 항목(위치 조합, 허용 확장자, 개수 제한, 결과 분류 등)은 코드가 아니라 `config` 파일에 두었습니다.
3. **결과는 숫자 코드로** — 변환 결과를 "성공/실패" 같은 글자가 아닌 코드(예: 1000, 2003)로 남기고, 코드 → 문구 변환은 설정 파일이 합니다. 문구·분류 기준이 바뀌어도 코드를 고칠 필요가 없습니다.

## 1. 프로그램 형태

| | |
|---|---|
| **기획 의도** | 인터넷 없이 외부에서 시연, 실제 툴과 같은 모습 |
| **구현 방식** | 실제 툴과 같은 Windows 기술(WinForms)로 만든 **exe 파일 하나**. 실행에 필요한 것을 모두 exe 안에 넣어 설치 없이 실행 |
| **이유** | 실제 툴과 같은 기술이라 창·버튼·목록의 모양과 느낌이 같고, 시연 PC 에 아무것도 설치하지 않아도 됨 |
| **한계** | 파일이 큼(약 66MB). 코드 서명이 없어 처음 실행 시 SmartScreen 경고가 뜰 수 있음 |
| **개선하려면** | 경고 제거 → [개발] 회사 코드 서명 인증서로 서명. 크기 축소 → [개발] ".NET 런타임 필요" 버전으로 배포(약 0.4MB, 시연 PC 에 .NET 8 설치 필요) |

## 2. 화면 배치와 디자인

| | |
|---|---|
| **기획 의도** | 기획서 디자인 가이드 + 실제 툴 화면과 같은 간격·크기 |
| **구현 방식** | 실제 툴 스크린샷에서 **여백·버튼 크기·열 간격을 픽셀 단위로 재서** 그 숫자대로 배치. 색상은 한곳(색상표)에 모아 둠 |
| **이유** | 자동 배치 기능을 쓰면 실제 툴과 미묘하게 달라지기 때문에, 잰 값을 그대로 쓰는 방식이 가장 정확함 |
| **동작 규칙** | 오른쪽 열(저장 위치·변환 상태)은 최소 384px 유지, 창을 줄이면 왼쪽 열만 줄어듦. 창 최소 너비 = 오른쪽 열 × 2. 화면 배율(125%, 150%)에 맞춰 모든 값이 같이 커짐 |
| **한계** | 콤보박스 높이는 Windows 기본값이라 실제 툴(30px)과 약간 다름. 목록 헤더 정렬(크기·암호화 헤더 왼쪽 정렬)은 실제 툴과 다름 |
| **개선하려면** | 색 변경 → [개발] 담당 위치 `UI/Theme.cs` (색상표, 색 코드만 바꾸면 됨). 여백·간격·버튼 크기 → [개발] `MainForm.cs` 위쪽의 숫자 모음(`MarginLeft`, `ColumnGap`, `RightColumnWidth` 등). 숫자만 바꾸는 작업이라 작은 요청 |

## 3. 버튼 활성화/비활성화 정책 (기획서 13p)

| | |
|---|---|
| **기획 의도** | 형식 미선택 시 전체 비활성, 조건이 다 갖춰져야 변환 시작 가능 등 |
| **구현 방식** | 무엇이든 바뀔 때마다(형식 선택, 파일 추가, 저장 위치 선택…) **"전체 상태 점검" 을 한 번 실행**해 모든 버튼을 다시 켜고 끔. 규칙이 한곳에 모여 있음 |
| **이유** | 버튼마다 따로 처리하면 규칙이 흩어져 누락이 생김. 한곳에 모으면 기획서 표와 1:1 로 대조 가능 |
| **현재 규칙** | 대상 위치 콤보: 형식 선택 + 변환 중 아님 + 목록 비어 있음 / 동일 폴더 저장: 대상·저장 위치가 모두 내 드라이브일 때만 / 변환 시작: 형식 + 가능한 파일(또는 폴더) 1개 이상 + (저장 위치 또는 동일 폴더) / 변환 중: 초기화·찾기·형식 변경 불가 |
| **개선하려면** | [개발] 담당 위치 `MainForm.cs` 의 `UpdateUiState`. 요청 예: "변환 시작 조건에 '불가 파일만 있을 때도 허용' 추가" |

## 4. 대상 위치 ↔ 저장 위치 조합 (기획서 13p 기본 변환 목록)

| | |
|---|---|
| **기획 의도** | MIP: 내 드라이브 → 내 드라이브/OneDrive/SharePoint, OneDrive·SharePoint → 내 드라이브. DRM: 모두 → 내 드라이브. 고객사에 따라 변동 |
| **구현 방식** | 허용 조합을 **설정 파일에 표로** 적어 두고, 콤보박스가 그 표를 보고 항목을 채움. 한쪽을 고르면 다른 쪽에는 맞는 항목만 표시 |
| **이유** | "고객사에 따라 정책 변동 가능" 이므로 코드에 박지 않음 |
| **개선하려면** | [설정] `config/conversion-policy.json` 의 `MipRoutes`, `DrmRoutes`. 예: DRM 도 OneDrive 저장 허용 → `DrmRoutes` 의 해당 줄 `Targets` 에 `"OneDrive"` 추가 |

## 5. 파일 추가 (드래그 / 찾기 / 탐색기 우클릭)

| | |
|---|---|
| **기획 의도** | 세 경로 모두로 파일 추가, 한 위치에서만 선택 가능 |
| **구현 방식** | 세 경로가 모두 **같은 "파일 추가" 처리**로 모임: 중복 제거 → 크기 계산 → 가능/불가 판정 → 목록에 추가 → 버튼 상태 점검 |
| **이유** | 경로마다 처리하면 경로별로 동작이 달라지는 버그가 생김 |
| **한계** | "찾기" 에서 파일과 폴더를 한 창에서 동시에 고를 수 없어 "파일 선택… / 폴더 선택…" 메뉴로 나눔 (Windows 기본 창의 제약) |
| **개선하려면** | [개발] `MainForm.cs` 의 `AddTargets` |

## 6. 탐색기 우클릭 메뉴 (V1.4)

| | |
|---|---|
| **기획 의도** | 파일 우클릭 → CloudConverter ▶ MIP로 변환 / DRM으로 변환 |
| **구현 방식** | Windows 는 우클릭 메뉴 목록을 **레지스트리(Windows 설정 저장소)** 에서 읽음. 프로그램이 실행될 때 "이 메뉴를 누르면 이 exe 를 이 파일로 실행하라" 는 항목을 현재 사용자 영역에 써 둠 |
| **이유** | 현재 사용자 영역은 관리자 권한 없이 쓸 수 있어 시연 PC 에서 바로 동작 |
| **한계** | Windows 11 의 **새 우클릭 메뉴(첫 화면)에는 넣을 수 없고 "더 많은 옵션 표시" 안에만** 나옴. 첫 화면에 넣으려면 코드 서명된 설치 패키지(MSIX)가 필요 |
| **개선하려면** | 메뉴 이름 → [개발] `AppEdition.cs` (지금 "CloudConverter(demo)"). 메뉴가 뜨는 확장자 → [설정] `extension-rules.json` 의 허용 확장자(같이 따라감). Win11 첫 화면 메뉴 → [개발·큰 작업] MSIX 패키징 + 서명 |

## 7. 창이 하나만 뜨기

| | |
|---|---|
| **기획 의도** | 여러 파일을 우클릭해도 창 하나에 모두 담김 |
| **구현 방식** | Windows 는 우클릭 시 파일 개수만큼 프로그램을 실행함. **가장 먼저 실행된 것만 창을 띄우고**, 나머지는 첫 번째 창에 "이 파일 추가해 줘" 라고 전달한 뒤 바로 종료 |

| **개선하려면** | 변환 중 추가 요청을 대기열에 넣었다가 끝나면 추가 → [개발] `MainForm.cs` 의 `ProcessPendingRequests` |

## 8. 암호화 가능/불가 판정 (V1.0 암호화 컬럼)

| | |
|---|---|
| **기획 의도** | 관리 툴에서 허용하지 않는 것만 "불가", 불가 파일이 섞여도 변환 가능(건너뜀) |
| **구현 방식** | 파일이 목록에 들어오는 순간 **허용 확장자 목록과 제외 폴더 목록**으로 판정. 불가 사유는 툴팁으로 표시 |
| **개선하려면** | [설정] 허용 확장자 → `extension-rules.json` 의 `AllowedExtensions`. 제외 폴더/폴더 키워드 → `conversion-policy.json` 의 `ExcludedDirectories`, `ExcludedDirectoryKeywords`. 불가 사유 문구 → `log-classification.json` |

## 9. 변환 처리 (시연판의 "가짜 변환")

| | |
|---|---|
| **기획 의도** | 실제처럼 보이되 실제 암호화는 하지 않음 |
| **구현 방식** | 파일마다 정해진 순서로 **판정**한 뒤, 성공이면 **원본을 그대로 복사**해 저장 위치에 결과 파일을 만듦 (내용은 원본과 같음) |
| **이유** | 결과 파일이 실제로 생겨야 "저장 위치에 파일이 생겼다" 를 보여 줄 수 있고, 원본 손상 위험이 없음 |

판정 순서 (위에서부터 먼저 걸리는 것 적용):

| 순서 | 조건 | 결과 | 시연에서 쓰는 법 |
|---|---|---|---|
| 1 | 원본 없음 | 실패 (2006) | — |
| 2 | 허용 안 된 확장자 / 제외 폴더 | 스킵 (3001 / 3004) | `.txt` 파일 넣기 |
| 3 | 파일 크기 0 | 스킵 (3002) | 빈 파일 넣기 |
| 4 | 파일명에 `_skip` | 스킵 (3003, 정책에 의한 스킵) | 이름 바꿔서 시연 |
| 5 | **이번 실행 중에 같은 형식으로 이미 변환한 파일** | 실패 (MIP 2001 / DRM 2002) | 같은 파일 두 번 변환 |
| 6 | (MIP 변환일 때) 실제로 암호화된 Office/PDF | 실패 (2003) | "이미 암호화된 보고서.docx" 샘플 |
| 7 | 파일명에 `_fail` | 실패 (2005, 권한 없음) | 이름 바꿔서 시연 |
| 8 | 위에 해당 없음 | **성공** (1000/1001) | — |

| | |
|---|---|
| **개선하려면** | 시연 시나리오용 키워드 → [설정] `conversion-policy.json` 의 `ForceFailKeywords`, `ForceSkipKeywords`. 실제 암호화 감지 끄기 → `DetectEncryptedFiles: false`. 진행 속도(파일당 시간) → `SimulatedSpeedMBps`, `MinFileDurationMs`, `MaxFileDurationMs`. 새 판정 조건 추가(예: 특정 크기 이상 실패) → [개발] `ConversionEngine.cs` + 결과 코드 추가 |

## 10. "이미 암호화된 파일" 기억 방식

| | |
|---|---|
| **기획 의도** | 실행할 때마다 처음 상태, 실행 중에는 변환한 파일 재변환 불가 |
| **구현 방식** | 변환한 파일의 **경로·크기·수정 시각을 메모리에만 기억**. 프로그램을 닫으면 사라짐 |
| **이유** | 파일에 저장하면 시연을 반복할 때 이전 기록 때문에 모두 실패하는 문제가 있었음(이전 버전에서 실제로 발생) |
| **한계** | 실제 암호화가 아니므로 다른 프로그램(Office 등)은 이 파일을 암호화된 것으로 인식하지 않음. 파일을 편집하면 기억이 무효화되어 다시 변환 가능 |
| **개선하려면** | 기억 범위 변경(예: PC 재부팅 전까지 유지) → [개발] `ProtectionStateStore.cs`, `AppServices.cs` |

## 11. 확장자 변환 규칙 (MIP 변환 결과 파일명)

| | |
|---|---|
| **기획 의도** | MS 문서의 MIP 확장자 규칙대로 결과 파일명 생성 |
| **구현 방식** | 규칙표를 설정 파일에 둠: Office·PDF 는 확장자 유지, `.txt`→`.ptxt`, `.jpg`→`.pjpg` 등 `p` 접두, 그 외는 `.pfile` 덧붙임 |
| **한계** | 현재 허용 확장자가 Office·PDF 뿐이라 시연에서는 확장자가 바뀌는 장면이 없음 |
| **개선하려면** | [설정] `extension-rules.json`. `.txt` 를 허용 확장자에 추가하면 `.ptxt` 로 바뀌는 장면을 시연할 수 있음 |

## 12. 저장 위치 파일명 중복 정책 (기획서 12p)

| | |
|---|---|
| **구현 방식** | 로컬→로컬: 기존 파일 덮어쓰기, 같은 작업 안에서 이름이 겹치면 두 번째부터 `파일명(1)`, `(2)`. 로컬↔클라우드: 기존 파일 유지, `파일명(1)` 형식. 폴더를 변환하면 저장 위치에 같은 폴더 구조로 저장 |
| **개선하려면** | 규칙 변경(예: 로컬→로컬도 덮어쓰지 않기) → [개발] `DestinationPlanner.cs`. 규칙 하나짜리 파일이라 작은 요청 |

## 13. 변환 진행 표시 (기획서 18p)

| | |
|---|---|
| **구현 방식** | 변환 시작 시 대상 파일을 모두 **"준비 중"** 으로 먼저 올리고, 순서대로 진행 막대를 채움. 실제 변환은 뒤에서 하고, 화면은 그동안 막대를 움직임(화면이 멈추지 않음) |
| **표시 규칙** | 성공 = 파란 막대 100%, 실패 = 진행하다 회색 "실패", SKIP = 연한 파랑, 폴더 = "변환 시작 → 변환 완료" 글자. 끝나면 성공 항목은 대상 목록에서 제거하고 요약 팝업 |
| **이유** | 시연에서는 변환이 너무 빨리 끝나면 진행 과정이 보이지 않으므로, 파일 크기에 비례한 **최소/최대 표시 시간**을 둠 |
| **개선하려면** | 표시 속도 → [설정] `conversion-policy.json` 의 `MinFileDurationMs`(최소, 기본 0.7초), `MaxFileDurationMs`(최대 4초). 색 → [개발] `UI/Theme.cs`. 요약 팝업 문구, 완료 항목 제거 여부 → [개발] `MainForm.Conversion.cs` |

## 14. 로그와 결과 분류 (기획서 20~21p)

| | |
|---|---|
| **기획 의도** | 성공/실패/스킵 분류는 확정 전 → 나중에 파일로 분류 기준을 넣을 수 있게 |
| **구현 방식** | 로그에는 **결과 코드만 저장**(예: 2003). 화면에 보일 때 `log-classification.json` 을 읽어 "실패 / 이미 암호화된 파일" 로 바꿈. 로그는 날짜별 CSV(엑셀로 열림) |
| **이유** | 분류 기준이 바뀌어도 **과거 로그까지 새 기준으로 다시 보임**. 코드 수정 없이 파일 교체만으로 변경 |
| **개선하려면** | [설정] `log-classification.json`: 결과 그룹 추가(예: "보류"), 코드별 그룹·분류명·툴팁 문구 변경. 로그 보기 창을 다시 열면 바로 반영. 새 판정 사유 자체를 추가하려면 [개발] 결과 코드 추가 |

결과 코드 전체 목록은 `README.md` 의 "로그 결과 분류" 표 참고.

## 20. 개발 요청서 쓰는 법 (개발자 / Claude 공통)

다음 네 가지를 적으면 바로 작업할 수 있습니다.

```
1. 현재 동작:   저장 위치가 OneDrive 일 때 "동일 폴더에 저장" 이 꺼진다
2. 원하는 동작: OneDrive → OneDrive 도 허용하고, 그때 체크박스가 켜지게
3. 근거:        기획서 13p 기본 변환 목록 v1.5 변경 (고객사 A 요청)
4. 담당 위치:   이 문서 3장(활성화 정책), 4장(위치 조합) — conversion-policy.json, UpdateUiState
```

"담당 위치" 는 이 문서 각 장의 **개선하려면** 칸에 적힌 이름을 그대로 쓰면 됩니다.
